# КП GRAFF.estate: смета → презентация в Figma

Одна из самых частых задач. Ядро обновляется автором набора. Свои правила и уроки — в `MY-RULES.md` (он важнее этого файла).

Связанные файлы:
- `templates/КП-GRAFF-интерактивная-презентация.md` — карта 24 слайдов, чек-лист данных, проверки.
- `projects/_образцы/` — образцы КП (GRAVION) и договора №542.
- Рабочий пример целиком: `projects/Икигай, Ижевск — КП/` (CONTEXT, разбор оценки, плагины).

---

## 1. Порядок работы

1. **Исходники.** Документация ЖК (ГП, АР, планы для маркетинга) и оценка тимлида в часах
   (Google Sheet). Разобрать документы: секции, этажность, число квартир, площадь благоустройства,
   МАФ, окружение. Зачем: понимать, откуда часы, и где тимлид закладывает запас
   (пример: `projects/Икигай…/01-analysis/разбор-оценки-тимлида.md`).
   **До сокращений сверх 20% — смотреть, что реально есть у клиента:** проект благоустройства, дизайн-проект интерьеров,
   число стилей фасадов, что вокруг участка. Каждое сокращение — с аргументом из материалов и сравнением с прошлыми КП
   (BRIGLI: из пяти предложенных сокращений руководитель оставил четыре). Риски «вверх» называть тоже.
2. **Смета.** Копия шаблона «Расчет_ЖК на Нахимовском» → заполнить часы (правила — §2).
   Папка проекта на Google Drive (аккаунт — в `MY-RULES.md`), файл `Расчет_ЖК <Название>_<дата>`.
   Часто нужны два варианта: с сокращением и «часы тимлида без сокращения» — отдельными файлами.
3. **Показ руководителю** обоих вариантов, согласование уровней, оборудования, сроков, оплаты.
4. **КП в Figma.** Копия последнего КП команды → перенос цифр и текстов локальным плагином (§4).
5. **Сверка** всей колоды (§5) и список вопросов к руководителю.
6. **CONTEXT.md проекта** — по ходу, не в конце: ссылки на папку Drive, сметы, Figma-файл, итоги по уровням,
   решения руководителя с датами, путь к финальному PDF в `03-delivery/`.

## 2. Правила сметы

- Шаблон: цена строки = ROUNDUP((часы×%×риск + часы×%) × ставка клиента; −3); надбавка 363%,
  риски 21%. База — пакет **Бизнес** (100%), остальные пакеты — проценты в строке.
- НДС **7%** сверху (УСН), сверять с договором. Оборудование — отдельной строкой в «Сводной».
- Часы тимлида режем **в среднем на 20%** (руководитель, 2026-09-29). Тимлид может сказать «не резать» —
  тогда отдельный файл без сокращения.
- Окружение: брать вариант «фактическая застройка» (для Икигая 1000 ч, срезано до 600).
  Перспективную застройку без документации не моделируем детально.
- «Сборка генплана + озеленение» и «Дороги и трафик» — в строку «Настройка глобальной 3D-сцены».
- Корпуса в названиях строк («Корпус 1.1 – 2.14») пишем, только если объём большой или домов
  несколько; иначе убираем.
- Работ, которых нет у тимлида (разработка, свет в интерьерах), — часы из шаблона.
- **Значения по умолчанию от руководителя (2026-10-05), часы тимлида поверх них не ставить:**
  набор моделей интерьеров (1 стиль) — 80 ч, меняется редко (на Премиуме коэффициент 200% сам даёт 160 ч на индивидуальный
  стиль); основной функционал — не ниже 200 ч.
- **Разработку (UI/UX, вёрстка, функционал, CRM, отладка) не резать по аналогии с моделированием.** Предлагать можно,
  решает руководитель: предложение «функционал 160 ч» он развернул до 200.
- Вёрстка зависит от числа помещений: 100 ч — многоквартирный дом (поинты по тысячам комнат), 80 ч — когда их расставлять не нужно.
- **Проект без МОП (коттеджи, таунхаусы):** обе строки МОП — 0 ч и убираются со слайдов работ; свет в интерьерах — вдвое меньше
  шаблона (40 ч вместо 80).
- **Коттеджный посёлок:** «Мастерплан» тимлида → строка «ландшафт генплана», «дороги окружения» → «Настройка глобальной
  3D-сцены». Ориентир по BRIGLI (≈495 участков, 3 типа домов): мастерплан 2000 ч тимлида → 600 ч, ниже руководитель резать
  не советует; окружение 1200 → 400 ч (вокруг поля и малоэтажка).
- **Бизнес-центры и другие нежилые объекты (руководитель, 2026-10-08, КП SEZAR):**
  - интерьеры, скорее всего, показывать не будем — только этажные планы без наполнения. Поэтому по каждому проекту
    **экстерьер и интерьеры считаем отдельно**: два листа и две строки в «Сводной», чтобы интерьеры убирались из КП одной строкой.
    Экстерьерный лист — фасады, генплан, МАФ, окружение, 3D-сцена, этажные планы и вся разработка; интерьерный — набор интерьеров,
    набор МОП, расстановка, наполнение МОП, свет. Интерьерный лист — копия экстерьерного; строки чужого блока — 0 ч с примечанием,
    на каком листе они посчитаны (не удалять: формулы шаблона);
  - МОП и офисы там сложнее жилья: **набор интерьеров — 120 ч** вместо дефолтных 80, **набор МОП — 200 ч** (руководитель назвал 200–220)
    вместо 160 тимлида; это выше, чем «тимлид −20%», ячейка «№» — без цвета, в примечании «Увеличено: было / стало / почему»;
  - на Стандарте и Старте интерьерный лист даёт 0 — это коэффициенты шаблона, не ошибка.
- **Несколько проектов или очередей в одном КП — как считать разработку, решает человек по конкретному проекту; спросить, не выбирать
  самому.** Встречались оба варианта: полностью на каждый проект (80 / 100 / 200 / 30 / 60), а экономию отдаём клиенту скидкой
  в «Сводной» — SEZAR, руководитель, 2026-10-08; база один раз + добавка 25 / 40 / 15 на очередь — Город звёзд.
- Объект, который показываем только снаружи и упрощённо (Сити 4 в КП SEZAR), — не отдельный проект: его фасад и генплан идут
  в лист соседнего объекта той же 3D-сцены, деление часов — только в примечаниях.
- **Цвет — только в ячейке столбца «№», строку целиком не красить:** красный — сильно сократили (сверх 20%), жёлтый — часы
  тимлида −20%, без цвета (серый шаблона) — не сокращали. Легенда — в E2:F5 листа.
- **Примечание к ячейке часов — до трёх блоков через пустую строку:** расчёт от часов тимлида; «Сокращено: было N ч, стало M ч»;
  «Почему: …» (суперкратко). Второй и третий — только там, где резали сверх 20%.
- Жёлтая заливка шаблона в B:D («персонализированные работы») спорит с цветами сокращений: в BRIGLI снята в B:D,
  в ценовых столбцах оставлена.

## 4. Правки в Figma: локальный плагин + мост, не MCP

**Основной способ с 2026-10-02 — мост.** Порядок в начале любой работы с колодой:
1. Поднять сервер в фоне: `node tools/figma-plugin/bridge.js` (порт 3055, только localhost).
2. Попросить человека открыть нужный файл в Figma Desktop и запустить плагин «GRAFF KP — тексты»; в окне должно быть
   «Мост с Claude: на связи». Окно не закрывать. Проверка с моей стороны: `node bridge.js send status` → `"plugin":true`.
3. `send info` — убедиться, что открыт тот файл и та страница; дальше `export` → сверка → `apply` / `run` → `export` + `png`.
Копирование JSON руками (шаги ниже) — запасной путь, если мост недоступен (облачная сессия, плагин не переимпортирован).
Подробности команд и грабли — в блоке «Мост» ниже и в журнале.

**Почему не MCP.** Figma MCP выполняет код на серверах Figma: локальные шрифты (TT Hoves Pro Trial,
Gilroy) там не загружаются, и любой текст в этих шрифтах менять нельзя. Плюс лимит ~20 вызовов
на бесплатном тарифе. MCP годится только для **чтения** (дамп текстов, скриншоты).

**Как работаем.** Плагин разработки в Figma Desktop — видит локальные шрифты, лимитов нет.

**Универсальный плагин `tools/figma-plugin/` (по умолчанию для текстовых правок):**
1. Человек один раз: Plugins → Development → Import plugin from manifest → `tools/figma-plugin/manifest.json`.
2. Запуск «GRAFF KP — тексты» → «Выгрузить» (все фреймы страницы или выделенные) → «Копировать» → присылает мне.
   Формат: `## frameId | имя фрейма`, затем `textId | текст` (перенос строки = ⏎).
3. Я сверяю со сметой и отдаю JSON правок:
   `{"edits":[{"id":"1:2","text":"5 594 000,00","from":"9 846 000,00"}],"remove":["id"],"hide":["id"]}`
   `from` — старый текст; если не совпал, правка пропускается. Без `from` плагин не даст заменить цену на текст и наоборот.
4. Человек вставляет JSON → «Применить» → видит «изменено / пропущено» с причинами.
   **Строки целиком** (без разового плагина): строка = общий контейнер указанных текстов, поднятый, пока у родителя
   нет других текстов. Для строки таблицы — 2 id (подпись + значение), для пункта списка — 1 id.
   - удалить: `"remove":[["idПодписи","idЗначения"]]` (строка id — удалить сам слой);
   - добавить: `"add":[{"like":[…],"after":[…],"as":"ключ","texts":{"id из like":"текст"}}]` — клон like после after;
     в `check` новые тексты — `"@ключ/id из like"`. Повторный запуск не плодит копии (тексты клонов обновляются по тому же ключу).
   - сноска на слайде: `"note":[{"like":"id текста-образца","in":"id слайда","as":"ключ","text":"…","x":0.04,"y":0.86,"w":0.3}]` —
     клон текста на слайд; x, y, w — доли ширины/высоты слайда, позиция ставится один раз (потом можно двигать руками).
     Вместо `y` можно `"bottom": px` — отступ от нижнего края слайда.
   - оформление куска текста: `"style":[{"id":"id или @ключ/id","from":0,"to":6,"bold":true,"strike":true,"fill":"#8a8a8a","scale":0.8}]` —
     from/to — позиции символов; scale — размер относительно последнего символа текста. Так делается строка бонуса:
     клон строки оборудования, значения «787 500,00⏎0,00», первая строка зачёркнута, серая и мельче; «Бонус:» жирным.
   Порядок: edits → add → note → style → remove → hide → check.
5. **Всегда класть в JSON блок `check`** — плагин пересчитает связи после правок (или по кнопке «Проверить суммы»):
   `"check":[{"name":"Сводная Старт итог","sum":["id","id","id"],"eq":"id"},{"name":"НДС Старт","pct":7,"of":"id","eq":"id"}]`
   Число берётся из последней строки текста (бонус «787 500,00⏎0,00» → 0), «отсутствует» = 0.
   Что проверять: строки слайда работ → «Сумма»; суммы → «Итого»; итог × 7% → НДС; итог + НДС → с НДС;
   сводная: разработка + оборудование + бонус → «Итого, без НДС»; «Разработка приложения» = итог слайда работ уровня.
   Плагин не пересчитывает сам: связанные цифры считаю из сметы и отдаю все в одном JSON.

**Мост: правки без копирования JSON (с 2026-10-02).** `tools/figma-plugin/bridge.js` — локальный сервер на `localhost:3055`;
окно плагина само забирает с него команды и возвращает результат. Человек только открывает файл и запускает плагин
(в окне строка «Мост с Claude: на связи»).
- Сервер: `node tools/figma-plugin/bridge.js` (в фоне, пока идёт работа). Проверка связи: `node bridge.js send status`.
- Команды: `node bridge.js send <команда> [payload.json | script.js | '{"inline":"json"}'] [--out файл]`:
  `info` (файл, страница, список фреймов), `export` (тексты; `{"ids":[…]}` — только эти фреймы), `apply` (JSON правок),
  `check`, `png` (`{"id":"…","scale":1}` → `--out слайд.png`, смотреть результат без экспорта PDF),
  `run` (тело async-функции с аргументом `figma`, результат через `return` — для структурных правок вместо разового плагина).
- Правки идут в тот файл, который сейчас открыт в Figma: перед `apply`/`run` сверять `info`.
- Команды принимаются только с токеном из временной папки и не с веб-страниц; облачной сессии мост недоступен.

**Сборка цифр колоды одним скриптом (с 2026-10-05, образец — `projects/BRIGLI…/02-solution/figma-build/build.js`).**
Данные сметы — массивами в начале файла, запуск `bridge.js send run build.js`. Скрипт правит титул и сводную, слайд-образец
«Основные работы» уносит на страницу «_шаблоны (не экспортировать)» и собирает из него слайды уровней (метка в pluginData);
повторный запуск удаляет свои слайды и строит заново — так вносится каждая смена часов. Перед запуском `verify()` сверяет суммы
данных, после — `export` собранных слайдов и скрипт сравнения с цифрами таблицы (id слайдов меняются при каждой пересборке).

**Структурные правки** (клонировать колонки и строки, переставлять плитки, переносить картинки) — отдельный
разовый плагин в `02-solution/figma-plugin/` проекта. Образцы — `tools/figma-plugin-examples/`. Новый `code.js`
подхватывается без повторного импорта; итог — в уведомлении и Plugins → Development → Show/Hide console.

**Экономия MCP при чтении:**
- Ответ MCP обрезается на ~20 КБ JSON; кириллица экранируется \uXXXX (×6), т.е. влезает ~3000 символов.
  Фильтровать: только цифры/имена клиента, короткие срезы.
- Всю страницу глазами — один `get_screenshot` узла страницы `0:1` с `maxDimension` = высоте страницы,
  потом резать на куски локально (`@napi-rs/canvas`).
- Чужой файл (только просмотр) MCP не читает вовсе — попросить «Duplicate to your drafts».

**Шрифты — первое, что проверить.** Если Figma при открытии показывает «Missing fonts», плагин не сможет менять тексты
в этих шрифтах («could not be loaded»). Колоды команды бывают в разных сборках: Икигай — «TT Hoves Pro Trial»,
«Характер» (Тюмень) — полный «TT Hoves Pro» + Bebas Neue Pro, Gotham Pro, PT Sans Pro. Нужны файлы шрифтов от дизайнеров.

**Грабли плагина (каждая стоила цикла правок):**
- `toLocaleString('ru-RU')` в песочнице не ставит пробелы разрядов → регулярка
  `String(n).replace(/\B(?=(\d{3})+(?!\d))/g, ' ') + ',00'`.
- Порядок ячеек брать из `children` (автолейаут), **не по координатам**: после clone/insert
  `absoluteTransform` устаревает → значения уезжают в соседние колонки.
- Не предполагать число слоёв в строке: в строках итога сводной был скрытый служебный слой «4»
  (6 детей вместо 5). Подпись = 5-й с конца, значения = 4 последних.
- `node.findAll` есть только у контейнеров — проверять `'findAll' in n` (иначе «not a function»).
- Структурные шаги (clone колонок/строк) делать идемпотентными: проверка «уже есть» или
  `setPluginData`. Иначе каждый перезапуск плодит копии.
- Картинки между файлами плагин не переносит: слайд-источник человек вставляет в файл (Ctrl+C/V),
  плагин копирует `fills` IMAGE.
- `n.characters = s` красит весь текст стилем первой буквы (зачёркнутая старая цена съела стиль новой).
  Менять только отличающийся кусок: `insertCharacters` + `deleteCharacters`.
- Менять текст по id узла + проверка, что старый текст похож на ожидаемый (цена на цену).

## 5. Сверка колоды перед показом

**Что смотреть и чем:**
- До правок — только выгрузка текстов из плагина (цифры и формулировки сверяются со сметой построчно).
- После правок — обязательно глазами: один `get_screenshot` страницы `0:1` (1 вызов MCP), резать локально.
  Без MCP — человек экспортирует колоду в PDF (File → Export frames to PDF), читаю PDF.
- Текстом не видно: чужие картинки и рендеры, плейсхолдеры на изображениях, разъехавшуюся вёрстку,
  нечитаемые подписи на светлых картинках.


- [ ] Титул: застройщик, ЖК, город — без следов прошлого клиента
- [ ] Нет упоминаний убранного уровня (сводная, радиус, интерьеры, слайды работ, оборудование)
- [ ] Итоги слайдов «Основные работы» = строке «Разработка приложения» в сводной; НДС и итог с НДС
- [ ] Суммы = «Сводная» в смете (перечитать таблицу, не по памяти)
- [ ] «Визуализация офиса продаж» — только материалы этого клиента, иначе слайд убрать
- [ ] Оборудование каждого уровня есть среди вариантов на слайде «Базовое оборудование»
